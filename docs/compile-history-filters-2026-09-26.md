# 컴파일 기록 필터 구현·검증

## 적용 범위

로컬 구현 완료. 배포, 운영 DB 변경, Git push는 수행하지 않았다.

컴파일 큐(`/queue`)에서 아래 조건을 조합한다.

- 기록 범위: 전체 / 공개 IDE / 공개 문제 연습 / 내 대회 기록
- 대회 선택, 문제 선택, 문제 제목 또는 ID 일부 검색
- 언어, 처리 상태, 판정, 작업 종류, 사용자 이름, 내 기록만
- 필터 초기화와 URL 기반 페이지 이동·뒤로 가기

텍스트 검색은 `적용` 버튼으로 적용하고 선택 상자는 즉시 적용한다. 대회·문제 목록은 **조회 권한이 있는 기록에 등장한 항목**이다. 제출이 없는 대회는 나오지 않는다. 목록은 각각 최대 200개이며 제목/ID 검색은 목록에 잘린 기록도 서버에서 검색한다. 기존 공개 기록 보관 정책은 바꾸지 않았다. 삭제된 과거 기록을 복구하는 기능은 아니다.

## 서버와 접근 범위

기존 `GET /api/v1/compiler/queue`에 `source`, `contestId`, `problemSearch`, `language`, `mine`을 추가했다. 기존 `problemId`, 사용자·판정·상태·작업 및 페이지 조건은 유지했다. 응답에 대회/문제 선택 목록과 기록 맥락을 추가했다.

공개 큐 관측 기록과 본인 대회 제출의 메타데이터를 SQL 조회로 합친다. 필터링 후 전체 개수·페이지를 계산하며, 같은 접수 시각에는 ID로 순서를 고정한다. 같은 원본 문제가 여러 대회에서 쓰여도 대회별로 구분해 선택·집계한다. 데이터 모델 마이그레이션이나 기록 복사는 없다.

- 비로그인 사용자는 공개 IDE·연습 기록만 조회한다. 내 기록/대회 전용 조건에는 로그인이 필요하다.
- 대회 제출은 관리자도 본인 것만 조회한다. 공개된 대회의 진행 중 참가자 또는 종료한 대회의 본인 기록만 포함한다. 초안·시작 전 대회 기록은 숨긴다.
- 일반 관측 기록에서도 비공개 문제와 대회 실행 ID에 연결된 항목을 제외한다. 건수·집계·선택 목록에도 같은 접근 범위를 적용한다.
- 대회 제출 코드, 숨김 테스트, 실행 payload/result는 조회 응답에 포함하지 않는다. 대회 스냅샷에서는 문제 제목만 선택한다.
- 저장되지 않은 대회 실행 시간·코드 크기는 `null`/`-`로 표시한다. 0으로 추정하지 않는다.
- 응답에 `Cache-Control: no-store`를 설정한다. UI는 계정/토큰과 필터별로 결과를 분리하고, 로그아웃·계정 변경 전 요청의 늦은 응답을 폐기한다.
- 조회는 읽기 전용이며 작업 실행·큐 복구·리스 획득을 하지 않는다. 위치/집계는 조회 가능한 관측 정보이지 전체 실행기 스케줄 순서를 보장하지 않는다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| 새 접근 제어·SQL 복합 필터 검사 | SQLite 9개 통과, PostgreSQL 9개 미실행 |
| 위 검사 + 기존 관측 큐·보관·대회 회귀 | 42개 통과, PostgreSQL 환경 요구 24개 건너뜀 |
| 프런트 전체 단위 테스트 | 34개 파일, 185개 통과 |
| 타입 검사 | 통과 |
| 프로덕션 빌드 | 통과, 산출물은 `.deploy/history-filters-final-build`에 격리 |
| 실제 로컬 HTTP API + SQLite + Edge 브라우저 | 5개 통과 |

서버 검사는 미참가/타인/관리자 조회, 초안·예정 비공개, 접수 시각 동률, 페이지 분리, 문자 `%`/`_`의 리터럴 검색, 범위 제한된 집계, 200개 선택 목록 경계, 숨김 데이터 미포함과 SELECT-only를 검증한다.

브라우저 검사는 55개 공개 기록과 서로 다른 두 대회의 본인 제출을 사용한다. 페이지 이동, 동일 원본 문제의 대회 구분, 선택 해제, 검색, 뒤로 가기, 실제 서버의 대회 응답 지연 중 로그아웃을 확인했다. 320/390/768px에서 페이지 가로 넘침 없음, 선택 상자 최소 너비, 아래 기록 목록까지 스크롤 가능 여부를 검사했다. 데스크톱과 모바일 캡처를 직접 검토했다.

중간 검증에서 발견한 문제와 조치:

- 동일 원본 문제의 선택 값이 겹침 → 대회/문제 복합 선택 값과 명시적 공개 맥락으로 수정하고 회귀 추가.
- 모바일 필터가 좁게 압축됨 → 작은 화면에서 한 행씩 배치, 페이지 전체 스크롤, 너비 검사를 추가.
- 첫 대회 복구 검사는 테스트 실행 환경에서 내장 워커를 꺼 타임아웃 → 워커가 필요한 기존 테스트에는 활성화해 재실행, 전체 통과. 제품 코드는 이 실패 때문에 변경하지 않음.
- 선택적 인증의 잘못된 토큰은 기존 정책상 공개 조회로 내려감 → 공개 정보만 남고 대회 전용 요청은 401임을 검증. 인증 정책을 임의 변경하지 않음.

## 재현

백엔드: 개발용 임시 SQLite 경로로 `DATABASE_URL`, 개발 환경과 테스트 전용 `SECRET_KEY`, `AUTO_INITIALIZE_DB=true`, `EMBEDDED_EXECUTION_WORKER=true`, 빈 `REDIS_URL`을 지정한 뒤 다음 검사를 실행한다. 운영 DB/키를 사용하지 않는다.

```text
python -m pytest tests/test_compile_history_filters.py tests/test_queue_observation.py tests/test_queue_retention.py tests/test_contests.py -q --tb=short
```

프런트:

```text
npm run test:run
npm run typecheck
npm run build -- --outDir ../.deploy/history-filters-final-build
```

브라우저: 백엔드에서 `python tests/history_filters_browser_server.py` 실행(새 임시 DB, 127.0.0.1:18003). 프런트는 `VITE_API_URL=http://127.0.0.1:18003`, `VITE_APP_BASE_PATH=/`로 지정해 `npm run dev -- --host 127.0.0.1 --port 4180 --strictPort` 실행 후:

```text
npx playwright test --config=playwright.history-filters.config.ts
```

이 fixture는 테스트용 계정과 기록을 자체 생성하며 실제 컴파일러를 실행하지 않는다. 운영용으로 띄우지 않는다. 캡처는 `.deploy/test-results/history-filters/`에 보관한다.

## 남은 외부 검증

이번 검증은 Windows Python 3.13/SQLite와 로컬 Edge 기준이다. 별도의 격리 PostgreSQL `TEST_POSTGRES_URL`을 제공하면 기존 매개변수화된 테스트로 PostgreSQL 분기를 실행할 수 있다. 운영과 동일한 Linux/고정 의존성 이미지, PostgreSQL 실행 결과와 대규모 이력 조회 부하 검증은 이번에 수행하지 않았다. 실제 TLE/MLE·언어별 제한 설계/구현은 이 필터 작업의 검증 결과에 포함하지 않는다.
