# 개인전 콘테스트

구현 상태: 로컬 구현·검증 완료, 배포 대기. **사용자의 명시적 배포 지시 전에는 main push, CI 재실행에 의한 자동 배포, 서버 배포를 하지 않는다.**

## 사용

콘테스트 메뉴의 기본 경로 `/contests`는 대회 카드 목록이다. 전체/진행 중/예정/종료 필터와 이름 검색을 제공하며, 각 카드의 일정·상태·참가자 수를 확인하고 클릭하면 해당 대회 상세로 이동한다. 상세 화면의 `콘테스트 목록` 링크로 돌아올 수 있다. 상세는 요약/일정/참가 버튼, 접이식 안내·규칙, 문제/스코어보드/내 제출 패널로 구분한다.

상단 콘테스트 메뉴에서 대회 목록을 연다. 관리자는 `대회 만들기`에서 제목·설명·한국 시각(KST)의 일정·문제 순서·고정 배점을 설정한다. 기존 공개 문제를 선택하거나 예제 및 숨겨진 테스트가 있는 신규 문제를 작성할 수 있다. 공개 체크 전에는 초안이며 관리자에게만 보인다.

로그인한 사용자는 시작 전 또는 진행 중 참가 신청할 수 있다. 진행 중 참가해도 시작·종료 시각은 모든 참가자에게 동일하다. 시작 후 참가자에게 문제를 공개하며 대회 IDE의 `대회 제출`로 제출해야 대회 점수를 얻는다. 상단 실행 버튼은 연습 실행이며 대회 제출을 대신하지 않는다.

스코어보드는 비로그인 사용자도 볼 수 있다. 진행 중 5초 간격으로 갱신한다. 내 제출 화면은 50개씩 조회하며 본인 코드만 열 수 있다. 대회 IDE의 코드/언어 저장 범위는 `contest:<contestId>:<contestProblemId>`로 일반 IDE·일반 문제 풀이와 분리한다.

## 채점과 순위

- 지원 언어: B++, C, C++, Python, Java, JavaScript. 기존 Docker 실행기와 공용 실행 큐를 재사용한다.
- 모든 예제 및 숨겨진 테스트를 통과해야 문제별 대회 배점을 한 번 받는다. 부분 점수는 없다.
- 총점 내림차순, 패널티 오름차순으로 정렬한다. 패널티는 마지막 득점 제출의 대회 시작 이후 경과 초 + 맞힌 문제의 첫 정답 이전 오답 수 × 300초다.
- 오답, 런타임 오류, 시간/메모리 초과만 오답 수에 포함한다. 컴파일 오류, 시스템 오류, 아직 못 푼 문제는 패널티에서 제외한다.
- 첫 정답 및 정답 이전 오답은 접수 시각 순으로 계산한다. 같은 접수 시각의 정렬 보조키는 제출 ID다. 채점 완료 순서에 영향을 받지 않는다. 점수·패널티 모두 같으면 공동 순위(1, 1, 3)다.
- UTC 시각으로 저장하고 API는 `Z`가 붙은 ISO 시각을 반환한다. UI는 서버 시각으로 보정하며 한국 시각과 KST를 표시한다.

## 보관과 공개

`contests`, `contest_problems`, `contest_participants`, `contest_submissions` 네 테이블을 기존 DB 초기화 과정에서 추가한다. 기존 테이블의 컬럼 변경은 없다. 대회 제출은 일반 제출 200개 보관 제한에 포함되지 않는다.

대회 공개 시 원본 내용·예제·숨겨진 테스트·일반 배점을 스냅샷으로 저장한다. 공개된 대회의 일정/대회 배점만 수정해도 기존 스냅샷은 유지된다. 공개 전 초안은 공개 시 최신 원본을 복사한다. 신규 대회 문제를 명시적으로 편집하면 시작 전에만 스냅샷도 변경할 수 있다. 시작 후에는 문제·배점·일정을 수정할 수 없다. 참조된 원본 문제는 삭제할 수 없다.

신규 문제는 공개된 대회가 끝날 때까지 일반 문제/제출/커뮤니티 경로에서 차단한다. 일반 문제 조회 조건에서 종료 시각을 직접 확인하므로 종료 작업이 지연돼도 종료 즉시 일반 목록에 편입된다. 초안 문제는 계속 비공개다. 숨겨진 테스트는 종료 후에도 일반 사용자에게 반환하지 않는다. 대회 채점 작업은 공용 큐에 사용자/문제 제목/문제 ID를 기록하지 않으며 실행기 예외 메시지도 비식별 메시지로 처리한다. 다른 참가자의 소스 조회 API는 없다.

## 내구성과 종료

제출 요청은 서버가 접수한 시각과 코드를 먼저 커밋하고 `202` 및 제출 ID/대기 상태를 반환한다. 인정 구간은 `startsAt <= receivedAt < endsAt`다. 요청마다 `requestId`를 보내며 같은 ID/내용을 재전송하면 기존 제출을 반환한다. 다른 내용으로 재사용하면 `409`다. 사용자당 대회별 미완료 제출은 최대 5개, 문제는 최대 26개, 문제당 테스트는 최대 200개다.

애플리케이션 lifespan에서 채점 작업자와 1초 간격 종료 작업을 시작한다. 작업자는 queued 제출 또는 만료된 running 제출을 조건부 UPDATE로 점유한다. 임대는 120초이며 20초마다 갱신한다. 정상 종료 시 다시 대기 상태로 돌리고, 비정상 종료 시 임대 만료 후 재처리한다. 결과는 임대 토큰이 일치할 때만 저장한다. 시스템 실패/중단은 최대 3번 시도 후 시스템 오류로 종료하며, 중복 점수는 지급하지 않는다.

종료 시 제출을 차단하고 미완료 제출이 있으면 `finalizing`(최종 채점 중)을 표시한다. 마감 전에 접수했지만 DB 잠금 때문에 종료 처리 뒤에 저장되는 요청도 인정하며 종료 처리를 재개한다. 채점 완료 후 원본 문제의 해결 기록과 스냅샷의 일반 문제 배점을 기존 점수에 반영한다. 대회 배점을 전체 점수에 더하지 않는다. 이미 해결한 문제는 지급하지 않는다.

종료 작업은 대회 행 및 사용자 행 잠금, 해결 기록 유일키, savepoint, 원자적 총점 증가로 반복 실행과 일반 풀이 동시 지급을 보호한다. 지급과 finalized_at은 같은 트랜잭션에 커밋한다. 기존 레이팅 캐시를 무효화하여 현재 계산 규칙으로 다시 조회하게 한다.

## 로컬 검증

백엔드 의존성이 설치된 환경에서 테스트용 `DATABASE_URL`을 지정하고 `backend`에서 `python -m pytest -q`를 실행한다. 프런트엔드는 `npm run typecheck`, `npm run test:run`, `npm run build`로 검사한다.

브라우저 통합 검증은 운영 주소와 완전히 분리한 로컬 전용 테스트다. 세 터미널에서 실행한다:

1. `backend`: `python tests/contest_browser_server.py` — 새 임시 SQLite DB를 매 실행 생성하고 127.0.0.1:18001에만 바인딩한다.
2. `frontend` (PowerShell): `$env:VITE_API_URL='http://127.0.0.1:18001'; npm run dev -- --host 127.0.0.1 --port 4175 --strictPort`
3. `frontend`: `npx playwright test --config playwright.contests.config.ts`

브라우저는 기본 설치된 Edge 채널을 사용한다. 다른 환경에서는 `PLAYWRIGHT_CHANNEL=chromium` 등 설치된 채널을 지정한다. **재실행 전 테스트 서버를 재시작해 새 DB를 사용한다.** 테스트 시각 변경 API와 테스트 계정은 해당 테스트 스크립트에만 있으며 운영 앱에서 import하지 않는다. 기본 Playwright 설정은 이 로컬 전용 suite를 제외한다.

이 로컬 테스트는 실행기만 테스트 대역이며 실제 인증/API/DB/공용 큐/대회 작업자/종료 작업을 사용한다. 관리자 생성 → 참가 → 6개 언어 템플릿 → 제출/정답 → 코드 저장/복원 → 순위표 → 종료/일반 공개/전체 점수 반영을 확인한다. **이 PC에는 Docker가 없어 실제 샌드박스의 6개 언어 대회 실행은 아직 로컬 통합 검증하지 못했다.** 배포 승인 후 실제 실행 환경에서 별도 확인해야 한다.

## 범위

개인전만 지원한다. 팀전, 가상 참가, 점수판 동결, 해킹, 대회 전용 레이팅은 포함하지 않는다. 기존 랜딩 홍보 문구는 변경하지 않았다.
