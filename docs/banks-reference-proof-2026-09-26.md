# J 기준 풀이: 주기적 역전쌍

상태: 독립 유도 및 로컬 대조 검증용. 원 출제처 해설이나 구현을 복사하지 않았다. 실제 6개 언어 채점·자원 측정 및 출처 이용 조건 검토는 별도다.

## 연산의 의미

자원을 `a[0..n-1]`, 양수 총합을 `S`라 하자. 누적합 `x[0]=0`, `x[i+1]=x[i]+a[i]`를 두고 모든 정수 인덱스에 `x[i+n]=x[i]+S`로 확장한다.

음수인 `a[i]=x[i+1]-x[i]`를 뒤집고 양옆에서 그 절댓값을 빼는 연산은 `x[i]`와 `x[i+1]`를 바꾸는 것과 같다. 주기가 있으므로 모든 주기에서 동시에 바뀐다. 원형 경계에서는 대표 누적합에 상수가 더해질 수 있지만 크기 비교는 바뀌지 않는다. n=2에서는 양방향 이웃이 같아 두 번 차감하며 이 표현과 일치한다. n=1은 양수 총합 조건 때문에 이미 완료다.

## 연산 횟수의 불변량

정수쌍 `(i,j)` 중 `i<j`이고 `x[i]>x[j]`인 쌍을 역전쌍이라고 하자. `(i,j)`와 `(i+n,j+n)`은 같은 주기적 역전쌍이다. 대표를 `0<=i<n`으로 정한다. S>0이므로 j가 충분히 커지면 역전이 사라져 개수 I는 유한한 비음수 정수다.

합법적인 연산은 인접한 역전 한 쌍을 교환한다. 다른 위치와의 비교는 두 위치 사이에서 교환되어 총수가 같고, 교환한 인접 쌍만 사라진다. 주기별 동일 교환을 한 묶음으로 세므로 I는 정확히 1 감소한다. n>=2에서 이 인접 교환들은 서로 겹치지 않는다.

음수가 남아 있으면 인접 역전이 있으므로 연산할 수 있다. 따라서 정확히 I번 후 모든 자원이 0 이상이 된다. 반대로 모든 자원이 0 이상이면 확장 누적합 전체가 비내림차순이므로 I=0이다. 모든 완료 순서는 같은 I번을 필요로 하며, 이것이 최소 횟수다.

## 유한 합으로 계산

대표 누적합의 각 쌍 `0<=i<j<n`을 생각하자.

- `x[i]>x[j]`이면 `(i,j+kn), k>=0` 방향의 개수는 `ceil((x[i]-x[j])/S)`이다.
- `x[i]<x[j]`이면 반대 방향 `(j,i+kn), k>=1`의 개수는 `ceil((x[j]-x[i])/S)-1`이다.
- 두 값이 같으면 0이다.

따라서 모든 무순서 쌍의 `ceil(abs(x-y)/S)` 합에서, 원래 순서상 엄격히 증가하는 누적합 쌍의 수를 빼면 I가 된다.

첫 합은 누적합을 정렬해 계산한다. 각 값의 유클리드 몫·나머지를 `x=qS+r, 0<=r<S`로 쓰면, 정렬된 두 값 x<=y에 대해 다음이 성립한다.

`ceil((y-x)/S) = q_y-q_x + [r_y>r_x]`

몫 차이 합은 누적 몫의 합으로 계산하고, 나머지 비교 횟수는 좌표 압축한 Fenwick tree로 센다. 두 번째 증가쌍 개수도 원래 순서를 순회하며 별도의 Fenwick tree로 센다. 전체 시간 O(n log n), 공간 O(n)이다. 음수의 몫/나머지는 **내림 나눗셈**이어야 한다. 0을 향해 버리는 언어에서는 나머지를 0..S-1로 보정한다.

## 수치 범위

대표 누적합 두 개의 차이는 `(n-1)*31999` 이하이고 S>=1이다. 각 쌍의 기여도는 그 이하이므로 전체 답은 `n*(n-1)/2 * (n-1)*31999 < 1.6e16`이다. 이는 충분히 보수적인 상한이며 signed 64-bit 범위 안이다. JavaScript Number의 정확 정수 범위를 보장하는 상한은 아니므로 기준 구현에는 BigInt를 사용한다. Python은 정수 오버플로가 없다. 실제 최대값이 이 보수적 상한에 도달한다는 주장은 아니다.

## 독립 확인

작은 입력은 문제 연산 자체를 구현한 BFS 최소 횟수와 대조한다. 빠른 구현과 별도로 O(n²) 유한 합도 대조한다. 회전·반전·양의 배수 변형, 모든 값이 비음수, 중복 누적합, 총합1, n=1/2와 최대 n 입력을 검사한다. 이 검사는 위 증명을 보조하며 원 출제처의 전체 데이터나 실제 런타임 성능 검증을 대체하지 않는다.
