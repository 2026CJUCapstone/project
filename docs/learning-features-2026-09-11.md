# 알고리즘 학습 기능 구현·검증 기록

## 범위

승인된 1·2·4·5 항목을 로컬에 구현했다. 운영 배포, Git push, main 병합, 운영 데이터 변경은 하지 않았다. 기존 프로필·설정·IDE·반응형 변경과 사용자 문서/삭제 내역을 보존했다.

- IDE 실행 결과의 `사용자 테스트`: 표준 입력, 예제 적용, 예상 출력 비교, stdout/stderr/종료 코드/실행 시간.
- `/learning`의 `문제집`: 공개 문제를 태그로 묶은 7개 과정, 난이도 순서, 개인 해결 진행도, 다음 미해결 문제로 이동.
- `복습`: 미해결·북마크·메모 있음·전체 필터, 문제별 개인 메모, 복습 완료 표시. 일반 문제 IDE에서도 편집 가능하다. 대회 문제 패널에는 노출하지 않는다.
- `추천`: 기존 해결 난이도와 주제별 해결 수를 이용하는 결정적 규칙. 해결한 문제는 제외하고 근거를 표시한다.
- 저장소 루트 `AGENTS.md`: 주 에이전트가 복잡한 설계/보안/동시성/테스트, Luna max가 가장 쉬운 독립 작업, Terra xhigh가 중간 난이도 독립 작업을 맡도록 기록했다. 메인은 모든 결과를 검토·통합한다.

이번 분담: Luna는 출력 비교 함수/단위 테스트, 마이그레이션 회귀 테스트와 라우트 테스트를 작성했다. Terra는 입력 테스트 패널과 학습 화면/API 클라이언트/간단한 화면 테스트를 작성했다. 메인은 백엔드 모델·권한·저장·추천·채점 통합, 동시성/실패 주입/계정 전환 테스트와 브라우저 통합을 담당했다.

## 동작과 데이터 계약

`/api/v1/learning` 아래에 다음 API를 추가했다.

| 경로 | 권한·동작 |
| --- | --- |
| GET `/tracks` | 공개 과정 목록, 로그인 시 개인 진행도 |
| GET `/tracks/{id}` | 문제 목록, `limit` 1~100/`offset` 페이지 조회 |
| GET `/recommendations` | 비로그인 입문 추천 또는 개인 추천, 최대 6개 |
| GET `/review` | 로그인 필수, `filter=unresolved/bookmarked/notes/all` |
| GET `/problems/{id}` | 본인 북마크·메모·복습 시각/현재 완료 여부·버전 |
| PUT `/problems/{id}` | 본인 기록 저장, 버전 불일치 409, 메모 최대 5,000자 |

응답은 `Cache-Control: private, no-store`. 사용자 ID는 토큰에서 결정하며 클라이언트가 지정할 수 없다. 관리자도 다른 사용자의 개인 메모를 조회하지 않는다. 삭제된 문제, 진행 전/진행 중 비공개 대회 원본, 시스템 게시판은 목록·추천·기록 API 모두에서 제외한다. 학습 목록에는 문제 본문·소스·테스트를 포함하지 않는다.

`problem_learning_records`는 `(user_id, problem_id)` 복합 키를 가진다. 일반 제출의 보관 제한과 독립적으로 북마크·메모·최근 유효 채점 정보를 저장한다. 제출 접수 시각으로 갱신하며 동일 시각은 ID로 결정적 순서를 부여한다. 이 tie-break는 동일 시각의 물리적인 접수 선후를 증명하지 않는다. 시스템 오류는 이전 복습 대상을 지우지 않는다.

일반 채점 결과·점수 원장·학습 기록은 기존 큐의 같은 publication 트랜잭션에 참여한다. 오래된 채점 완료는 최신 기록을 덮지 않는다. 정답 해결 여부는 기존 `UserProblemScore`를 이용한다. 복습 완료 이후 새 오답을 접수·채점하면 복습 대상이 다시 열린다. 대회 종료의 해결 반영은 기존 점수 원장을 통해 진행도/추천에 반영되며, 진행 중 대회 기록을 학습 API에 공개하지 않는다.

입력 테스트는 기존 `/api/v1/executions`의 `kind=run` 경로를 쓰며 `problem_id`를 보내지 않는다. 문제 제출·정답·점수를 만들지 않는다. 브라우저는 기본 서버 제한과 같은 65,536 UTF-8 bytes를 검사하며 서버의 설정된 한도도 별도로 적용된다. 패널을 닫거나 계정/문제를 바꾸면 클라이언트 대기는 취소한다. 이미 접수된 서버 작업의 취소를 보장하는 기능은 아니다.

출력 비교는 CRLF/CR을 LF로 통일한다. `정확히 비교`는 그 외 공백과 마지막 개행을 유지한다. `줄 끝 공백 무시`는 각 줄 끝의 공백/탭과 마지막 빈 줄을 무시한다. 중간 공백·빈 줄은 유지하고 최초 차이 줄을 표시한다. 이것은 공식 채점 결과가 아니다.

추천은 해결 난이도의 중앙값(짝수 개는 위쪽 값)보다 한 단계 높은 난이도를 목표로 한다. 해결 기록이 없으면 iron5부터 시작한다. 가까운 난이도 후보 최대 200개 안에서 난이도 거리 → 적게 해결한 태그 → 이전 시도 여부 → ID 순으로 최대 6개를 선택한다. 전체 문제에 대한 전역 최적 추천이나 학습된 AI 모델이 아니다. 과정은 고정된 태그 그룹이며 관리자용 문제집 편집기는 이번 범위에 포함하지 않는다. 해당 태그 문제가 없으면 준비 중으로 표시한다.

## 마이그레이션

런타임 스키마 버전은 `20260911_learning_v11`이다. 배포 승인 후에는 기존 직렬화된 `python -m app.initialize` 절차로 API/워커보다 먼저 스키마를 준비해야 한다. 초기화는 새 테이블을 만들고 기존에 남아 있는 완료 제출을 한 번 역채운다. 재실행해도 북마크·메모·점수를 초기화하지 않는다. 이미 보관 제한으로 삭제된 과거 오답은 복원할 수 없다.

## 검증 결과

- 프런트 전체: 32개 파일, **179개 테스트 통과**.
- TypeScript `tsc --noEmit`: 통과.
- Vite 루트 경로 빌드와 최종 `/webcompiler/` 경로 빌드: 통과. 최종 빌드 3.77초.
- 관련 백엔드: **39개 통과, 29개 건너뜀**. 새 학습 테스트 8개와 기존 초기화/큐/채점/제출 회귀를 포함한다. 건너뛴 항목은 `TEST_POSTGRES_URL`이 없는 PostgreSQL 변형이며 통과로 세지 않았다.
- 학습 브라우저 통합: **4개 통과**. 실제 Edge·Monaco·JWT/API·임시 SQLite·durable queue를 사용했다. 데스크톱 1440px/모바일 390px에서 과정→문제 IDE→메모/북마크 저장→입력 테스트→복습 목록 갱신→추천을 확인했다. 사용자 테스트 전후 점수/공식 제출 수가 같음을 확인했다. 오답→정답→중복 정답 후 복습/진행도/추천/점수 원장도 확인했다.
- 기존 IDE/헤더 브라우저 회귀: **4개 통과**. 비로그인·긴 닉네임의 홈/IDE를 320~1920px 16개 너비에서 검사(64개 레이아웃). 겹침·가려짐·화면 밖 컨트롤, 메뉴 이동, 그래프 닫기/재열기와 언어별 기본 템플릿 검증.
- 계정/문제 전환 중 늦은 private 응답, 같은 계정의 토큰 교체 중 입력 테스트 응답, 입력 변경 후 오래된 실행 결과, 중복 저장 차단, 서로 다른 세션의 동시 첫 저장(한 건 성공/한 건 409), 채점 publication 실패 주입의 전체 rollback, 중복 정답의 점수 지급 한 번, 제출 보관 제한 후 복습 정보 유지, 비공개/삭제 문제 비노출을 검증했다.
- 확인 과정에서 수정한 회귀: 시스템 게시판이 추천에 섞이는 문제, 같은 복습 필터 재클릭 시 빈 목록 고정, 필터 전환 중 이전 항목 표시, 메모 저장 후 목록 미갱신, 이전 문제의 메모 요청이 남는 문제, 과거 복습 시각 때문에 다시 열린 문제가 완료로 표시되는 문제.
- 화면 스크린샷: `frontend/test-results/learning.local-*/`의 desktop/mobile learning/custom-test/review 이미지. 테마 전환이 끝난 뒤 캡처하여 육안 확인했다.

## 격리 로컬 실행과 남은 검증

학습용 fixture는 `backend/tests/learning_browser_server.py`다. 새 임시 SQLite를 매 실행 생성하며 운영 데이터나 기존 로컬 DB를 읽지 않는다. 백엔드 포트 18002, 프런트 4176을 사용한다. 기존 18001/4175는 검사 시 연결이 거절되어, 그 DB를 새 데이터로 대체하지 않고 별도 포트를 사용했다.

재현 순서:

1. backend에서 `python tests/learning_browser_server.py` 실행.
2. frontend에서 `VITE_API_URL=http://127.0.0.1:18002`를 설정하고 Vite를 `--host 127.0.0.1 --port 4176 --strictPort`로 실행.
3. `playwright test --config=playwright.learning.config.ts` 실행. 설치된 Edge를 사용한다.
4. 기존 헤더/IDE 회귀는 `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4176`, `PLAYWRIGHT_API_ORIGIN=http://127.0.0.1:18002`를 설정해 `playwright.ide-local.config.ts`로 실행할 수 있다.

**이 fixture의 컴파일러는 42 또는 지정된 실패 값을 반환하는 테스트 대역이다.** 실제 6개 언어의 컴파일·stdin 전달·샌드박스 제한이 이번 변경에서 검증됐다고 볼 수 없다. Docker를 설치하거나 운영에 접속하지 않았다. 실제 실행기 이미지의 언어별 입출력 회귀, 격리 PostgreSQL의 새 학습/동시성/초기화 테스트, 대규모 문제/메모 데이터에서의 부하 확인이 남아 있다. PostgreSQL 테스트에는 운영 URL 대신 명시적으로 승인된 격리 테스트 URL을 제공해야 한다.
