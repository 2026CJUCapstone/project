# 컴파일 결과 탐색 개선 및 검증

## 추가 구현: 여섯 가지 탐색 기능

| 기능 | 사용 방법과 구현 |
| --- | --- |
| 변수 흐름 | SSA 명령 옆 값 버튼 또는 ‘변수 흐름’의 함수별 값을 선택한다. 정의·사용 명령은 보라색으로 강조하고 블록 간 전달은 점선으로 연결한다. 정의·사용 목록에서 소스로 이동할 수 있다. |
| 선택 집중 | 코드 선택 후 ‘선택 영역만 보기’를 누르면 대응 노드만 남긴다. ‘주변 연결 펼치기’로 한 단계씩 이웃을 추가하고 해제하면 전체 그래프로 돌아간다. |
| 최적화 이유 | ‘최적화 비교’에서 같은 코드의 O0/O1 출력을 요청한다. 실제 컴파일러의 함수별 변환 카운터를 한국어 이유와 횟수로 표시한다. |
| 단계 비교 | ‘나란히 보기’에서 AST·SSA 또는 IR·ASM을 선택한다. 소스 선택을 공유하며, 넓게 보기 버튼과 Esc를 지원한다. 작은 화면에서는 위아래로 배치한다. |
| 매핑 안내 | 상세 패널·SSA 명령·IR/ASM 행에 표현식/문장/함수·블록/소스 범위/근사/생성/연결 없음 배지를 표시한다. AST ID·원본 ID와 실제 노드 유형만 근거로 사용한다. |
| 예제 안내 | 조건문·반복문·함수 호출 예제를 선택하고 불러오기→컴파일→단계 선택 순서로 탐색한다. 코드 대체 전 확인하며, 코드가 예제와 다르면 단계 이동을 잠근다. |

### 컴파일러 및 API 계약

- pinned Bpp 소스의 JSON 출력에만 additive patch를 적용한다. 파일은
  `runtime/compiler-patches/exploration.bpp`와 `apply_exploration.py`이며,
  기대한 소스 형태가 달라지거나 이중 적용되면 빌드를 중단한다.
- 각 SSA 명령에 version 1 `valueFlow`를 추가한다. 정의·사용은 함수 범위의
  레지스터 ID이며, 호출 인자는 포인터 숫자를 추측하지 않고 내부 호출 정보를
  읽는다. φ 입력도 구조화된 레지스터에서 읽는다.
- 각 함수에 version 1 `optimizationSummary`를 추가한다. 실제 상수 대체,
  상수 분기 단순화, 중복 계산 제거, 복사·저장 제거, 도달 불가 블록 제거,
  φ/대수식 단순화 횟수를 사용한다. 단순히 예약된 패스 실행 횟수는 제외한다.
- 서버는 `instructionDetails`와 `optimizationSummaries`로 정규화한다.
  잘못된 ID/카운터는 제외하며 구버전의 opaque 호출 데이터는 불완전으로 표시한다.
- 런타임 빌드 서명에 패치 두 파일과 새 검증 게이트를 포함했다.
  이미지 빌드 시 `verify_bpp_exploration.py`가 O0/O1 JSON과 호출 인자 및 실제
  변환 카운터를 검사한다. 출력에 필요한 메타데이터가 없으면 빌드가 실패한다.

### 정확성 경계

- 최적화 이유는 **SSA 함수 단위 변환 보고**다. 특정 diff 행에 임의로 이유를
  붙이지 않으며, 보고 정보가 없는 구버전에서는 이유를 추정하지 않는다.
- 값 흐름은 정적 정의·사용 관계이고, 실행 순서·실행 횟수나 런타임 값은 아니다.
  외부 정의나 여러 정의도 숨기지 않고 표시한다. 그래프 연결선은 최대 300개,
  검색 목록은 앞 100개이며 명령·정의·사용 목록은 유지한다.
- 힙 슬라이스 반환처럼 별도 descriptor를 사용하는 일부 명령은 현재 사용
  목록을 완전히 제공하지 않는다. `complete=false` 경고가 표시되며 연결을
  꾸며내지 않는다. 함수 호출·일반 산술·분기·φ의 값은 구조화하여 제공한다.
- SSA 값 이름은 원본 변수 이름과 다를 수 있다. 같은 `r1`이라도 함수가 다르면
  다른 값으로 취급한다. 매핑 범위가 넓다는 이유만으로 표현식 연결로 표시하지 않는다.

### 추가 검증 현황

- 전체 프런트 단위·통합 테스트: 69파일, 388개 통과.
- 타입 검사 및 프로덕션 빌드 통과.
- 컴파일/실행 계약/런타임 빌드 및 새 이미지 게이트 계약 테스트 총 71개 통과.
- 계정·문제 범위가 바뀌면 그래프 결과와 소스 선택을 지우고 진행 중 요청을
  취소한다. 범위를 바꿨다가 되돌아오는 경우도 요청 세대로 구별하여 늦은
  응답·오류가 새 결과를 덮어쓰거나 자동 실행을 유발하지 않게 했다.
- Chrome E2E 두 시나리오에서 기존 조작과 새 여섯 기능을 검증했다.
  1440/1024/390px, 양쪽 소스 강조, 값 연결선, 선택 노드 수와 이웃 확장,
  예제 대체 확인/취소, 매핑 배지, 최적화 근거 표시를 확인했다.
  모바일 두 패널 아래로 footer가 배치되는지도 검사한다. 이 브라우저 검증의
  API 응답은 테스트 fixture이며 실제 컴파일러 실행과 구분한다.
- 실제 컴파일러 변경은 자원 제한 임시 컨테이너에서 별도 self-host 빌드 및
  예제 검증으로 확인한다. `scripts/check_compiler_exploration_runtime.py` 사용.
  기본 실행은 세 예제와 최종 게이트를, `--gate-only`는 복합 조건문·함수 호출
  게이트만 검사한다. `--ssh-host`, `--ssh-port`, `--image`를 명시해야 한다.
- **배포·push·운영 설정/데이터 변경 없음.** 운영 적용에는 수정된 웹앱/서버뿐
  아니라 새 샌드박스 이미지의 빌드·승인·교체가 필요하다. 기존 이미지에는
  새 최적화 보고와 완전한 호출 인자 정보가 없다.

### 실제 컴파일러 최종 확인

- 패치를 적용한 컴파일러를 서버의 별도 컨테이너에서 self-host 빌드했다.
  CPU 1개, 메모리/스왑 상한 1 GiB, PID 64개, 네트워크 없음, 읽기 전용 루트,
  임시 파일 시스템 256 MiB를 사용했다. 운영 DB·큐·볼륨은 연결하지 않았다.
- 조건문·반복문·함수 호출 예제의 O0/O1 여섯 조합은 JSON 생성, IR JSON,
  어셈블·링크·실행까지 완료했으며 예상 반환값 1/6/5를 확인했다.
  이 실행의 마지막 별도 게이트는 표준 라이브러리를 포함한 불필요한 출력으로
  시간 제한에 걸렸으므로 전체 실행 성공으로 처리하지 않았다.
- 실제 사용자 코드만 조회하도록 게이트를 맞춘 뒤 별도로 다시 빌드·검증했다.
  최종 `--gate-only` 실행은 384.6초에 성공했다. O0/O1 각각 실제 실행 반환값 5,
  호출 정의 `r5` 및 입력 `r1`, 구조화된 값 흐름의 `complete=true`를 확인했다.
  출력은 수정한 로컬 백엔드 파서로 읽어 두 경우 모두 계약 검사를 통과했다.

| 복합 조건문·호출 검증 | SSA 명령 수 | 상수 피연산자 대체 합계 | 상수 분기 단순화 | 도달 불가 블록 제거 |
| --- | ---: | ---: | ---: | ---: |
| O0 | 11 | 0 | 0 | 0 |
| O1 | 6 | 5 | 1 | 1 |

- 긴 SSH 실행 및 바이너리 업로드 중 연결이 끊기는 환경 문제가 있었다.
  종료 컨테이너에서 증거를 회수하고 정리했으며, 작은 소스 입력을 보내는
  기본 경로와 연결 유지 설정으로 최종 확인했다. 이 서버에서는 선택적 바이너리
  캐시 업로드 경로 대신 기본 실행을 사용한다.
- 마지막 검증 후 `webcompiler.test=exploration` 컨테이너가 남지 않은 것을 확인했다.
- 이 결과는 변경된 컴파일러와 파서의 격리 검증이다. 전체 배포용 이미지 빌드,
  운영 이미지 교체, 실제 서비스 API에서의 재검증은 별도 배포 승인 뒤 수행한다.

## 수정 범위

- 컴파일러의 UTF-8 바이트 위치를 Monaco의 UTF-16 위치로 한 번 변환한다.
  LF/CRLF, 한글, 이모지, 가져온 파일, 범위를 벗어난 위치를 구분한다.
  샌드박스 파일 기록에서도 원문 줄바꿈을 보존한다.
- 여러 문장을 드래그하면 선택에 포함된 각 문장을 표시한다. 작은 표현식을
  선택했을 때는 이를 둘러싼 함수 전체를 불필요하게 강조하지 않는다.
- 컴파일 이후 코드가 바뀌면 이전 결과임을 표시하고 소스 위치 이동을 중단한다.
- 노드 드래그 위치 유지, 검색 및 결과 순환, 다중 선택, 관계 집중, AST 접기,
  배치 방향/초기화, 화면 맞춤, 미니맵, 상세 정보 및 소스 이동을 제공한다.
  선택을 바꾸기만 했을 때는 자동 배치를 다시 계산하지 않는다.
- AST/SSA/IR/ASM 연결 탐색에서 명시적인 컴파일러 ID 연결과 소스 범위가
  겹치는 항목을 별도로 표시한다. 연결 정보가 없으면 추측해서 만들지 않는다.
- 같은 소스의 최적화 전후 출력을 비교한다. 기존 대기열을 사용하고,
  취소·문제 이동·계정 변경·소스 변경 후 도착한 결과는 반영하지 않는다.
- CFG 지배 블록, 자연 루프, 도달 불가능 블록과 정적 경로 재생을 제공한다.
  함수 진입점은 Bpp의 블록 생성 순서에서 보존한다. 분석은 500블록,
  경로 탐색은 200단계로 제한한다.
- 작은 화면에서는 도구 모음과 그래프를 분리하고, 화면 크기 변화 및
  숨겨졌던 패널을 열 때 그래프를 다시 맞춘다. 노드 선택만으로 모바일
  그래프 탭에서 벗어나지 않으며 명시적인 소스 이동은 코드 탭을 연다.

## 실제 출력에서 확인한 IR 누락

사용 컴파일러는 runtime/bpp-ref.txt의 Creeper0809/Bpp
2d596233f45973394a5d951c40b11f78171c8870이다.

이 버전의 unified JSON은 --views에 ir을 넣어도 IR을 포함하지 않는다.
기존 서버는 따라서 위치 정보가 없는 dump-ir 텍스트로 대체했다.
별도 dump-ir-json 기능과 샌드박스 모드는 이미 존재하므로, 서버를 해당
JSON 경로 우선으로 수정했다. 출력은 ssa 키 안에 stage=ir로 들어온다.
실제 SSA 결과를 IR인 것처럼 재사용하지 않는다. 구버전에서 JSON이 지원되지
않을 때만 기존 텍스트 출력으로 내려간다.

앞선 소스 매핑 수정에서는 컴파일러 원본 자체를 변경하지 않았다. 이번 추가
기능은 위의 출력 전용 패치를 사용한다. 초기 조사에서 의심했던 ASM 캡처 복원
순서는 호출된 함수가 컨텍스트를 다시 설정한다는 점을 확인해 결함 판정을 철회했다.

## 경계

- 경로 재생은 정적 CFG를 따라가는 학습 기능이다. 실제 실행을 기록하는
  디버거나 런타임 트레이서가 아니며 분기 선택과 반복 진입은 사용자가 결정한다.
- 컴파일러가 만든 일부 분기/점프의 소스 범위는 전체 if/while/for문이다.
  없는 표현식별 정보를 만들어 더 정밀한 연결이라고 표시하지 않는다.
- 최적화 비교는 출력 비교이지 실행 속도 벤치마크가 아니다.
- 위 기능 구현 검증 시점에는 배포, 커밋, push 및 운영 설정 변경을 수행하지 않았다.

## 후속 UI 정리 및 배포 준비

- 사용자 승인으로 UI 수정, push, main 병합, 제한된 빌드 환경 준비와 짧은 점검 배포를 진행한다.
- 단계 선택을 세그먼트 형태로 정리하고, 컴파일 상태·분석 도구·검색과 캔버스의 영역을 구분했다.
- 노드와 패널은 공통 slate/blue 표면을 사용하며 선택·검색·값 흐름 강조는 구별한다.
- 노드 상세는 그래프 위 팝업이 아니라 캔버스 아래 전용 영역이다. 브라우저 검사로 두 영역의 비겹침을 확인한다.
- 1440/1024/390px의 가로 넘침, 모바일 단계 버튼, 밝은/어두운 테마를 확인한다.
- 새 런타임의 정확한 SHA/이미지/digest 승인 절차는 docs/basic-pool-autodeploy.md에 기록했다.
- 릴리스 후보 전체 이미지 빌드와 운영 API 검증은 배포 이후 증거로 별도 기록한다.
